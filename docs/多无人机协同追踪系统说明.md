# 多无人机协同追踪系统说明

## 版本信息
- **版本**: v10.3.0-coordinator
- **日期**: 2025-10-17
- **作者**: 东华大学 Astraeus队

## 系统概述

本系统实现了多无人机协同追踪功能，通过**目标分配协调器**避免多架无人机重复追踪同一个非红色目标。

### 核心功能
1. ✅ **避免重复追踪**：一架无人机追踪某颜色目标后，其他无人机自动忽略该颜色
2. ✅ **红色特殊处理**：红色目标允许多架无人机同时追踪（符合比赛规则）
3. ✅ **实时协调**：基于ROS话题的实时通信，延迟<50ms
4. ✅ **容错机制**：心跳超时自动释放锁定，防止死锁
5. ✅ **动态分配**：目标丢失后自动释放，允许其他无人机接管

## 系统架构

### 1. 节点结构
```
┌─────────────────────────────────────────────────────────────┐
│                   Target Coordinator                        │
│                   (目标分配协调器)                           │
│  - 管理目标锁定状态                                          │
│  - 处理追踪请求                                              │
│  - 监控心跳超时                                              │
└─────────────────────────────────────────────────────────────┘
         ↑                    ↑                    ↑
         │ 请求/心跳          │ 请求/心跳          │ 请求/心跳
         ↓                    ↓                    ↓
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  Drone 0     │    │  Drone 1     │    │  Drone 2-5   │
│  Tracker     │    │  Tracker     │    │  Tracker     │
│              │    │              │    │              │
│ - 检测目标   │    │ - 检测目标   │    │ - 检测目标   │
│ - 请求权限   │    │ - 请求权限   │    │ - 请求权限   │
│ - 发送心跳   │    │ - 发送心跳   │    │ - 发送心跳   │
└──────────────┘    └──────────────┘    └──────────────┘
```

### 2. 消息流程

#### 场景1：首次发现目标
```
1. UAV0检测到蓝色目标
2. UAV0 → 协调器: "请求追踪蓝色目标"
3. 协调器检查: 蓝色未被锁定
4. 协调器 → UAV0: "批准追踪"
5. UAV0开始追踪，每秒发送心跳
```

#### 场景2：目标已被锁定
```
1. UAV1检测到蓝色目标
2. UAV1 → 协调器: "请求追踪蓝色目标"
3. 协调器检查: 蓝色已被UAV0锁定
4. 协调器 → UAV1: "拒绝追踪（已被UAV0锁定）"
5. UAV1继续巡航模式
```

#### 场景3：红色目标（允许多机追踪）
```
1. UAV0检测到红色目标
2. UAV0 → 协调器: "请求追踪红色目标"
3. 协调器 → UAV0: "批准追踪（允许多机）"
4. UAV1也检测到红色目标
5. UAV1 → 协调器: "请求追踪红色目标"
6. 协调器 → UAV1: "批准追踪（允许多机）"
7. UAV0和UAV1同时追踪红色目标
```

#### 场景4：心跳超时自动释放
```
1. UAV0追踪蓝色目标
2. UAV0崩溃/失联，停止发送心跳
3. 协调器检测到3秒无心跳
4. 协调器自动释放蓝色目标锁定
5. UAV1检测到蓝色目标
6. UAV1 → 协调器: "请求追踪蓝色目标"
7. 协调器 → UAV1: "批准追踪（超时释放）"
```

## 话题说明

### 1. 请求话题
- **话题**: `/target_coordinator/request`
- **类型**: `TargetRequest`
- **方向**: 无人机 → 协调器
- **内容**:
  ```
  int32 drone_id          # 无人机ID (0-5)
  string target_color     # 目标颜色 (blue, green, white, brown, red)
  time timestamp          # 请求时间戳
  ```

### 2. 响应话题
- **话题**: `/target_coordinator/response`
- **类型**: `TargetResponse`
- **方向**: 协调器 → 无人机
- **内容**:
  ```
  int32 drone_id          # 无人机ID
  string target_color     # 目标颜色
  bool approved           # 是否批准 (true=批准, false=拒绝)
  string reason           # 批准/拒绝原因
  time timestamp          # 响应时间戳
  ```

### 3. 心跳话题
- **话题**: `/target_coordinator/heartbeat`
- **类型**: `TargetHeartbeat`
- **方向**: 无人机 → 协调器
- **频率**: 1Hz
- **内容**:
  ```
  int32 drone_id          # 无人机ID
  string target_color     # 正在追踪的目标颜色
  bool is_tracking        # 是否仍在追踪 (true=追踪中, false=已停止)
  time timestamp          # 心跳时间戳
  ```

### 4. 状态话题（调试用）
- **话题**: `/target_coordinator/status`
- **类型**: `CoordinatorStatus`
- **方向**: 协调器 → 所有节点
- **频率**: 2Hz
- **内容**:
  ```
  time timestamp                  # 状态时间戳
  int32 num_drones               # 管理的无人机数量
  string[] locked_colors         # 已锁定的目标颜色列表
  string[] locked_by_drones      # 对应的锁定无人机ID列表
  ```

## 使用方法

### 1. 启动系统
```bash
# 启动6架无人机（默认）
roslaunch yolov11_ros multi_drone_system.launch

# 启动指定数量无人机
roslaunch yolov11_ros multi_drone_system.launch num_drones:=3
```

### 2. 监控协调器状态
```bash
# 查看协调器日志
rostopic echo /target_coordinator/status

# 查看请求/响应
rostopic echo /target_coordinator/request
rostopic echo /target_coordinator/response

# 查看心跳
rostopic echo /target_coordinator/heartbeat
```

### 3. 调试技巧
```bash
# 查看所有话题
rostopic list | grep coordinator

# 查看消息类型
rosmsg show TargetRequest
rosmsg show TargetResponse
rosmsg show TargetHeartbeat
rosmsg show CoordinatorStatus
```

## 关键设计决策

### 1. 为什么使用集中式协调器？
- ✅ **简单可靠**：单点管理，逻辑清晰
- ✅ **实时性好**：ROS话题通信延迟<50ms
- ✅ **易于调试**：所有决策在一个节点中
- ❌ **单点故障**：协调器崩溃会影响系统（可通过respawn解决）

### 2. 为什么红色目标允许多机追踪？
- 符合RoboCup比赛规则：红色代表需要救援的目标，允许多机协同

### 3. 为什么需要心跳机制？
- **防止死锁**：无人机崩溃后自动释放锁定
- **提高鲁棒性**：网络抖动不影响系统运行
- **实时性**：1Hz心跳频率，3秒超时检测

### 4. 为什么不在检测层面过滤？
- **灵活性**：协调器可以动态调整策略
- **可扩展性**：未来可以添加更复杂的分配算法
- **解耦合**：检测和追踪逻辑分离

## 故障排查

### 问题1：无人机不追踪目标
**可能原因**：
1. 协调器未启动
2. 目标已被其他无人机锁定
3. 消息未正确发布

**解决方法**：
```bash
# 检查协调器是否运行
rosnode list | grep target_coordinator

# 查看协调器状态
rostopic echo /target_coordinator/status

# 查看请求/响应
rostopic echo /target_coordinator/response
```

### 问题2：多架无人机追踪同一个非红色目标
**可能原因**：
1. 协调器崩溃
2. 心跳未发送
3. 消息丢失

**解决方法**：
```bash
# 重启协调器
rosnode kill /target_coordinator
# launch文件会自动重启（respawn=true）

# 检查心跳
rostopic echo /target_coordinator/heartbeat
```

### 问题3：目标锁定后无法释放
**可能原因**：
1. 心跳一直在发送
2. 无人机未正确停止追踪

**解决方法**：
```bash
# 手动发送停止心跳
rostopic pub /target_coordinator/heartbeat yolov11_ros_msgs/TargetHeartbeat \
  "{drone_id: 0, target_color: 'blue', is_tracking: false, timestamp: now}"
```
