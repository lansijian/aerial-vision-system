# 坐标转换差异问题分析

## 问题描述

从记分系统截图可以看出：
- **红色目标**（无人机1识别）：误差仅1.70m ✅
- **棕色目标**（无人机0识别）：误差高达30.76m ❌
- **绿色目标**（无人机0识别）：误差15.77m ❌

具体数据：
```
棕色: Ground Truth (-19.0, -5.2) -> Detected (-18.4, -36.0)
      Y轴误差: -30.8m

绿色: Ground Truth (-39.5, -35.8) -> Detected (-23.9, -38.1)  
      X轴误差: 15.6m
```

## 可能的原因分析

### 1. 距离参数t计算过大

如果无人机高度是4米（3米飞行高度+1米偏移），目标高度0.9米：
```
高度差 = 0.9 - 4 = -3.1米
如果ray_enu[2] = -0.1（射线接近水平）
则 t = -3.1 / -0.1 = 31米
```

这会导致巨大的位移误差。

### 2. 云台角度问题

代码中假设云台pitch为-45度，但实际可能不同：
- 如果实际云台角度接近水平（如-10度）
- ray_enu[2]会很小，导致t值异常大

### 3. 相机旋转矩阵问题

可能存在：
- 四元数处理错误
- 坐标系变换顺序错误
- 相机安装矩阵定义错误

### 4. 参数读取问题

虽然参数在launch文件中正确配置，但可能：
- namespace导致参数读取失败
- 默认值被使用

## 已实施的改进

1. **运行调试工具**
   ```bash

   python debug_actor_info_publisher.py 0
   python debug_actor_info_publisher.py 1
   ```

2. **检查日志输出**
   - 查看"[警告] 计算距离异常"
   - 查看"[警告] 位移过大"
   - 查看射线方向值

3. **验证云台角度**
   - 检查实际云台是否为-45度
   - 可能需要订阅云台状态话题

4. **对比两架无人机**
   - 为什么无人机1正常而无人机0异常？
   - 是否存在配置差异？

## 临时解决方案

当前代码已添加安全限制：
- 位移超过30米时会被限制
- t值超过50米时使用基于检测框的估计距离

这应该能缓解极端误差，但根本问题仍需解决。
