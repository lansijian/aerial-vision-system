# 坐标系统问题总结报告 - v9.5.7

## 问题概述

在多机协同系统中，两架无人机的坐标转换存在严重差异：
- **无人机1（红色目标）**：误差1.70m ✅
- **无人机0（棕色目标）**：误差30.76m ❌

## 调试数据分析

### 1. 无人机1（正常工作）
```
位置链：
local_position: (22.17, -8.46, 3.14)
    ↓ +偏移(3, -3, 1)
世界坐标: (25.17, -11.46, 4.14)
    ↓ 坐标变换
目标位置: (23.68, -10.02)

红色目标真实位置: 约(24, -10)
误差: < 2m
```

### 2. 无人机0（异常）
```
位置链：
local_position: (-18.67, -25.84, 3.03)
    ↓ +偏移(0, -3, 1)
世界坐标: (-18.67, -28.84, 4.03)
    ↓ 坐标变换
目标位置: (-17.96, -25.48)

棕色目标真实位置: (-19.0, -5.2)
Y轴误差: -25.48 - (-5.2) = -20.28m
```

## 问题根源

### 1. 无人机飞行位置异常
无人机0的local_position Y坐标为-25.84，这表明：
- 无人机从起飞点(0, -3, 1)向南飞行了约26米
- 远离了目标区域（目标在Y=-5.2附近）

### 2. 坐标系理解问题
当前系统假设：
- MAVROS local_position = 相对于起飞点的位置
- 世界坐标 = local_position + 起飞点位置

但实际情况可能更复杂：
- 航点文件可能使用不同的坐标系
- local_position的参考点可能不是简单的起飞点

### 3. 航点配置问题
```xml
<!-- multi_drone_system.launch中的配置 -->
<!-- 无人机0使用waypoints_drone_1.json（反向路线） -->
<param name="waypoint_file" value="$(find yolov11_ros)/scripts/waypoints/waypoints_drone_1.json" />

<!-- 无人机1使用waypoints_drone_0.json（正向路线） -->  
<param name="waypoint_file" value="$(find yolov11_ros)/scripts/waypoints/waypoints_drone_0.json" />
```

路线交换可能导致无人机0飞到了错误的区域。

## 坐标转换流程

### 当前实现
```python
# 1. 获取无人机位置
drone_x = self.current_pose.position.x
drone_y = self.current_pose.position.y
drone_z = self.current_pose.position.z

# 2. 应用偏移（如果配置）
if self.coordinate_offset_x != 0.0 or self.coordinate_offset_y != 0.0 or self.coordinate_offset_z != 0.0:
    drone_x += self.coordinate_offset_x
    drone_y += self.coordinate_offset_y
    drone_z += self.coordinate_offset_z

# 3. 射线计算
ray_camera = self._pixel_to_camera_ray(u, v)
R_cam_to_enu = self._compute_camera_rotation_matrix()
ray_enu = R_cam_to_enu @ ray_camera

# 4. 地面交点
t = (target_height - drone_z) / ray_enu[2]

# 5. 目标位置
actor_x = drone_x + t * ray_enu[0]
actor_y = drone_y + t * ray_enu[1]
```

### 技术细节正确性
- ✅ 相机参数：cx=320.5, cy=180.5（已修正）
- ✅ 四元数处理：归一化和符号处理
- ✅ 云台旋转：完整的三轴旋转矩阵
- ✅ 射线计算：数学上正确
- ❌ 坐标系偏移：需要根据实际情况调整
