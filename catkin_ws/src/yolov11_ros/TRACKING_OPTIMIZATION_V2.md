# 追踪优化v2 - 提高响应速度

## 📊 终端数据分析

### 发现的问题

从运行日志分析：

```
[中心追踪] 偏移:(u=-307px, v=-34px)   ← 严重左偏
[中心追踪] 偏移:(u=+258px, v=-44px)   ← 严重右偏
[中心追踪] 偏移:(u=-206px, v=-80px)   ← 左偏
[中心追踪] 偏移:(u=+161px, v=-98px)   ← 右偏
```

**关键发现：**
1. ❌ 目标频繁严重偏离中心（±200-300px）
2. ❌ `yaw_rate`频繁达到限幅值（±0.500）
3. ❌ 响应速度不够，无法快速对齐

### 代码错误

```python
UnboundLocalError: local variable 'yaw_gain' referenced before assignment
```

死区内没有赋值`yaw_gain`，但日志尝试输出。

---

## ✅ 优化方案

### 1. **修复UnboundLocalError**

#### 问题代码
```python
if abs_u < 10:
    yaw_rate = 0.0  # 死区
else:
    yaw_gain = ...  # 只在else内赋值

# 日志输出yaw_gain（错误！死区内未定义）
rospy.loginfo(f"增益:{yaw_gain:.4f}")
```

#### 修复方案
```python
# ✅ 去除死区，所有情况都计算yaw_gain
if abs_u < 80:
    yaw_gain = self.yaw_gains['very_close']
elif abs_u < 150:
    yaw_gain = self.yaw_gains['close']
# ... 

# 现在yaw_gain始终有值
```

### 2. **提高偏航增益（33-67%）**

#### 问题
从终端看，`yaw_rate`频繁达到±0.5限幅，说明增益和限幅都太保守。

#### 调整
| 分级 | 原值 | 新值 | 提升 |
|------|------|------|------|
| very_close (< 80px) | 0.0012 | **0.0020** | +67% |
| close (80-150px) | 0.0025 | **0.0040** | +60% |
| medium (150-220px) | 0.0040 | **0.0060** | +50% |
| far (> 220px) | 0.0060 | **0.0080** | +33% |

**计算示例（u=-307px）：**
- 原值：`yaw_rate = -(-307) × 0.006 = 1.842 → 平滑 → 限幅0.5`
- 新值：`yaw_rate = -(-307) × 0.008 = 2.456 → 平滑 → 限幅0.8`

### 3. **提高最大偏航率**

```python
# 原值
max_yaw_rate = 0.5  # rad/s

# ✅ 新值
max_yaw_rate = 0.8  # rad/s (提高60%)
```

**原因：**
- 从日志看，经常达到±0.5限幅
- 限幅太低限制了响应速度
- 0.8 rad/s ≈ 46°/s，是合理的转速

### 4. **提高平滑系数**

```python
# 原值
yaw_smooth_alpha = 0.30  # 30%新值 + 70%旧值

# ✅ 新值
yaw_smooth_alpha = 0.50  # 50%新值 + 50%旧值
```

**原因：**
- 原值0.30太保守，反应太慢
- 提高到0.50，50%新值+50%旧值，平衡响应和平滑
- 更快响应目标移动

## 📈 对齐状态判断

### 放宽对齐标准

```python
# ✅ 新标准
is_centered = abs_u < 50    # ±50px内认为对齐（原±15px）
is_distance_ok = abs(size_error) < 0.20  # ±20%误差（原±15%）
```

**原因：**
- 原标准±15px太严格，几乎无法达到
- ±50px是合理的对齐标准（640px图像宽的7.8%）
- 允许一定误差，避免过度调整

## ⚠️ 注意事项

### 1. 可能的副作用
- 响应更快，但可能略微增加抖动
- 如果抖动明显，可降低平滑系数到0.40

### 2. 观察指标
- `u_offset`：应在±50px内稳定
- `yaw_rate`：不应频繁达到±0.8限幅
- 状态：应大部分时间显示"✅对齐"或"🔄调整中"

### 3. 极限情况
- 如果人快速移动（>3m/s），可能依然无法完美对齐
- 这是正常现象，系统会持续追踪

## 🎓 经验总结

### 关键教训
1. **终端数据是最好的调试工具**
   - 实际偏移量（-307px）揭示问题
   - 限幅值（0.5）说明参数不足

2. **保守参数不一定好**
   - 原以为0.0012-0.006够用
   - 实际需要更大的响应速度

3. **平滑与响应的平衡**
   - 0.30太保守，响应慢
   - 0.50是更好的平衡点

4. **观察实际效果，动态调整**
   - 参数不是一成不变的
   - 根据实际表现优化
