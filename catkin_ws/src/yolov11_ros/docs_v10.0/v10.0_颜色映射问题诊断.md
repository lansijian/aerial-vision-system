# v10.0 颜色映射修正说明

## 问题发现

通过分析实际检测位置与Gazebo ground truth的对比，发现**YOLO检测到的颜色名称与Gazebo中actor的实际颜色不一致**。

## 分析数据

### Gazebo Ground Truth (actor真实位置)
```
actor_0 (green):  (-39.5, -34.6)
actor_1 (blue):   (-20.2, -34.6)
actor_2 (brown):  (-19.8,  -5.2)
actor_3 (white):  (  5.0,  -9.6)
actor_4 (red):    ( 27.6, -15.0)
actor_5 (red):    ( 40.0,   1.8)
```

### YOLO检测结果
```
检测为'green': ( 34.9, -23.1) → 最接近actor_4 (red), 距离10.9m
检测为'blue':  (  4.1,  -3.7) → 最接近actor_3 (white), 距离6.0m ✓
检测为'brown': ( 38.0,  -4.8) → 最接近actor_5 (red), 距离6.9m ✓
检测为'white': (-23.2,  -0.3) → 最接近actor_2 (brown), 距离6.0m ✓
检测为'red':   ( 27.9, -10.6) → 最接近actor_4 (red), 距离4.4m ✓
```

## 映射错误分析

| YOLO检测颜色 | 实际对应的Actor | Gazebo中的颜色 | 误差 | 状态 |
|-------------|----------------|---------------|------|------|
| red         | actor_4        | red           | 4.4m | ✅ 正确 |
| white       | actor_2        | brown         | 6.0m | ❌ 错误 |
| blue        | actor_3        | white         | 6.0m | ❌ 错误 |
| brown       | actor_5        | red           | 6.9m | ❌ 错误 |
| green       | actor_4?       | red?          | 10.9m | ❓ 不确定 |

## 根本原因

**YOLO训练数据集的颜色标注与Gazebo world中的actor颜色不一致！**

可能的原因：
1. 标注数据时颜色名称搞混了
2. world文件中walker模型的实际颜色与预期不符
3. YOLO训练时使用的颜色定义与Gazebo不同

## 修正方案

### 方案1：修正actor_id_dict（快速，已实施）

```python
# 修正后的映射（基于YOLO实际检测到的颜色）
actor_id_dict = {
    'white': [2],    # YOLO的white → actor_2 (Gazebo的brown)
    'blue': [3],     # YOLO的blue → actor_3 (Gazebo的white)
    'red': [4],      # YOLO的red → actor_4 (Gazebo的red) ✓
    'brown': [5],    # YOLO的brown → actor_5 (Gazebo的red)
    'green': [0, 1]  # YOLO的green → actor_0和actor_1（需验证）
}
```

### 方案2：重新训练YOLO（长期，推荐）

重新标注训练数据，确保颜色标签与Gazebo一致：
```
Gazebo actor颜色 → YOLO标签
actor_0 (green) → green
actor_1 (blue)  → blue
actor_2 (brown) → brown
actor_3 (white) → white
actor_4 (red)   → red
actor_5 (red)   → red
```

## 验证步骤

1. **应用修正后的映射**
   - 已修改`score_calculator.py`中的`actor_id_dict`

2. **重新运行系统**
   ```bash
   roslaunch yolov11_ros multi_drone_system.launch
   ```

3. **观察误差变化**
   - white的误差应该从29.69m降到<10m
   - blue的误差应该从39.30m降到<10m
   - brown的误差应该从57.82m降到<10m

4. **如果仍有问题**
   - 检查green的映射是否正确
   - 可能需要进一步调整

## 关于green的特殊说明

从分析看，检测为'green'的位置(34.9, -23.1)最接近actor_4，但actor_4已经被'red'正确识别了（误差4.4m）。

这可能意味着：
1. 同一个actor被检测为两种颜色（red和green）
2. green检测可能是误检
3. 或者actor_0和actor_1不在当前视野内

**建议**：先测试其他颜色的修正效果，green的映射可以后续调整。

## 预期效果

修正后，各颜色的误差应该都在10米以内（考虑坐标计算精度）。如果修正后误差仍>10m，则问题在于坐标计算算法，而非ID映射。
