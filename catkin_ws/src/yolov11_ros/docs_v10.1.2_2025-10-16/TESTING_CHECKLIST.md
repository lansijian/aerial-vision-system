## 关键验证点

### ❌ 不应该出现的情况

1. **控制冲突**：
   ```
   ❌ 不应该看到两个"控制权"日志同时出现
   ❌ 不应该有抖动现象
   ```

2. **航点不执行**：
   ```
   ❌ 起飞完成后应该立即开始航点飞行
   ❌ 不应该停在空中不动
   ```

3. **追踪方向错误**：
   ```
   ❌ 无人机0追踪时不应该方向反向
   ❌ 应该看到"速度修正"日志
   ```

### ✅ 应该出现的情况

1. **平稳飞行**：
   ```
   ✅ 航点飞行平稳，距离逐渐减小
   ✅ 追踪平稳，目标保持居中
   ```

2. **控制权清晰**：
   ```
   ✅ 每个时刻只有一个"控制权"日志
   ✅ 模式切换时控制权正确交接
   ```

3. **坐标稳定**：
   ```
   ✅ 坐标平滑，不大幅跳变
   ✅ 误差应该<1米（对比Gazebo真实位置）
   ```

## 问题排查

### 如果航点不执行

检查日志：
```bash
# 应该看到
✅ 无人机0: 控制权已交接给waypoint_navigator
🚁 无人机0: 开始航点飞行
📍 无人机0: 设定航点0 (-15.0, 0.0, 3.0)

# 如果没有看到，检查
1. waypoint_navigator是否启动
2. flight_mode是否正确发布
3. 航点文件是否加载成功
```

### 如果无人机0追踪反向

检查日志：
```bash
# 应该看到
⚠️ 速度修正: invert_x=True, invert_y=True, yaw=True
[速度修正] 无人机0 原始:(...) 修正后:(...)

# 如果没有，检查launch文件参数配置
```

### 如果坐标误差大

观察日志：
```bash
[坐标-red] 原始:(X1,Y1) 平滑:(X2,Y2) | 无人机:(...) | 距离:...m

# 对比Gazebo中actor的真实位置
rostopic echo /gazebo/model_states

# 计算误差
error = sqrt((X2 - X_true)^2 + (Y2 - Y_true)^2)

# 如果误差>1米，检查spawn_offset参数
```
