## 版本信息

## 🔴 关键问题（需紧急修复）

### 1. 无人机0控制反向问题
**问题描述**：
- 无人机0的控制命令（前后左右）全部反向
- 航点飞行和目标追踪都受影响
- 无人机1控制正常

**影响范围**：
- 航点导航功能
- 人体追踪功能  
- 所有涉及速度控制的模块

**可能原因**：
1. 无人机0的初始偏航角可能有180度偏差
2. PX4/MAVROS对无人机0的坐标系配置可能不同
3. 机体坐标系转换存在问题
4. sdf文件中的model配置可能有差异

**临时解决方案**（不推荐）：
- 硬编码判断drone_id==0，反转速度命令
- 给无人机0的偏航角加180度偏移

**问题**：
- 硬编码方案不利于6机扩展
- 没有找到根本原因

### 2. 版本混乱问题
**问题描述**：
- 从v10.0.1尝试优化到v10.1，引入复杂算法后误差增大
- 回退到v10.0.1，但修改了部分代码
- 又尝试v10.2简化版本，效果不佳
- 现在代码是多个版本混合，难以维护

**影响**：
- 代码可读性差
- 难以追踪修改历史
- 功能不稳定

## 🟡 功能问题

### 3. 坐标精度问题
**现状**：
- 当前坐标误差约2米
- 官方要求误差<1米
- Y轴误差更大

**原因分析**：
- 坐标系转换可能有系统偏差
- spawn_offset参数可能不准确
- 相机标定参数需要微调

### 4. 追踪模式切换问题
**已修复部分**：
- 话题名称已修正为`/request_tracking_mode`和`/request_waypoint_mode`
- 添加了飞行模式监听

**待优化**：
- 模式切换有时不够流畅
- 目标丢失后的恢复逻辑需要改进

## 📝 代码质量问题

### 6. 代码组织问题
- 存在多个存档版本，但版本管理混乱
- 部分代码有硬编码（如drone_id==0的判断）
- 调试日志过多，影响性能
- 缺少统一的配置管理

### 7. 参数化不足
- 很多参数直接写在代码中
- 缺少动态配置能力
- 扩展到6机需要修改大量代码

## 🔧 重构建议

### 优先级1：解决控制反向问题
1. **根本原因分析**
   - 检查PX4配置文件
   - 比较两架无人机的MAVROS参数
   - 分析初始化时的姿态差异
   
2. **通用解决方案**
   - 添加`velocity_transform`参数矩阵
   - 支持每架无人机独立配置
   - 避免硬编码

### 优先级2：代码重构
1. **模块化设计**
   - 将坐标转换独立成模块
   - 统一速度控制接口
   - 分离配置和逻辑

2. **参数化配置**
   ```yaml
   drone_config:
     drone_0:
       velocity_invert_x: true  # 或false
       velocity_invert_y: true  # 或false
       yaw_offset: 0  # 或180
     drone_1:
       velocity_invert_x: false
       velocity_invert_y: false
       yaw_offset: 0
   ```

3. **版本管理**
   - 清理冗余存档
   - 建立清晰的版本命名规则
   - 使用Git分支管理

### 优先级3：性能优化
1. 减少日志输出
2. 优化坐标计算算法
3. 提升响应速度
