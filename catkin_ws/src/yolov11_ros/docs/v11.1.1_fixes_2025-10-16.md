# v11.1.1 修复记录 - 2025年10月16日

## 修复的问题

### 1. 两架无人机不能同时起飞问题 ✅
**问题描述**：两架无人机不能同时起飞，存在时序冲突。

**解决方案**：
- 修改mission_controller.py，根据drone_id设置不同的initial_delay
- drone_0: 1.0秒延迟
- drone_1: 1.5秒延迟 
- 修改launch文件中的initial_delay参数

### 2. 解锁时间过长问题 ✅
**问题描述**：每次解锁需要很长时间，影响比赛效率。

**解决方案**：
- 减少OFFBOARD模式设置时的setpoint发送次数（100次→30次）
- 减少解锁前的心跳信号发送次数
- 优化状态检查频率

**效果**：
- 原本需要5秒的OFFBOARD模式设置现在只需1.5秒
- 整体起飞时间缩短约3-4秒

### 3. 起飞后不执行航点飞行问题 ✅
**问题描述**：起飞完成后，无人机悬停不动，不执行航点任务。

**解决方案**：
- 修复mission_controller.py中vel_pub未定义的问题（使用_send_setpoint代替）
- 优化起飞完成后的航点发布时机
- 添加调试日志确保waypoint_mission正确激活

### 4. 行人追踪优先级设置 ✅
**问题描述**：需要确保行人追踪优先级高于航点飞行。

**已验证的实现**：
- target_tracker在航点模式下持续检测目标
- 检测到目标立即发送追踪请求
- mission_controller收到请求后切换到TRACKING模式
- waypoint_mission在非waypoint模式时自动停止发布控制命令

### 5. 追踪完成后返回航点任务 ✅
**问题描述**：行人消失后需要自动返回航点任务。

**已验证的实现**：
- 目标丢失1.5秒后自动请求返回航点模式
- mission_controller切换回WAYPOINT模式
- waypoint_mission继续从上次中断的航点开始执行

## 关键代码修改

### mission_controller.py
```python
# 1. 动态initial_delay设置
self.initial_delay = rospy.get_param('~initial_delay', 1.0 + self.drone_id * 0.5)

# 2. 减少setpoint发送次数
for i in range(30):  # 原本是100次

# 3. 修复vel_pub问题
self._send_setpoint(0.0, 0.0, 0.1)  # 替代vel_pub.publish()
```

## 系统架构确认

### 控制流程
1. **WAYPOINT模式**：waypoint_mission → MAVROS（直接控制）
2. **TRACKING模式**：target_tracker → mission_controller → MAVROS（速度融合）

### 模式切换逻辑
- 航点飞行中检测到行人 → 立即切换到追踪模式
- 行人丢失1.5秒 → 自动返回航点模式
- 模式切换通过话题通信，各模块独立响应

1. 确保航点文件存在且格式正确
2. YOLO检测置信度阈值设置为0.3（launch文件中）
3. 追踪模式下的最低置信度为0.7（target_tracker内部）
4. 目标丢失超时时间为1.5秒
