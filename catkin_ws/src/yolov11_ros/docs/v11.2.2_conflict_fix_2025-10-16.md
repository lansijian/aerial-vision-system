# v11.2.2 控制冲突修复 - 2025年10月16日

## 问题描述

用户反馈：无人机在航点任务中一直原地抖动

## 问题原因

经过检查发现，`mission_controller.py`和`waypoint_mission.py`都在发布到同一个MAVROS话题：
```
/{vehicle_type}_{drone_id}/mavros/setpoint_raw/local
```

这导致了控制命令冲突：
- waypoint_mission发布航点控制命令
- mission_controller在某些状态下也发布命令（即使是空命令）
- 两个命令源产生冲突，导致无人机抖动

## 解决方案

### 修改mission_controller.py

确保在WAYPOINT模式下，mission_controller绝对不发布任何命令：

```python
# 修改前：IDLE状态总是发布
elif self.mission_state in [MissionState.TAKEOFF, MissionState.LANDING, MissionState.ARMING, MissionState.IDLE]:
    should_publish = True

# 修改后：IDLE状态检查flight_mode
elif self.mission_state in [MissionState.TAKEOFF, MissionState.LANDING, MissionState.ARMING]:
    should_publish = True
elif self.mission_state == MissionState.IDLE and self.flight_mode != FlightMode.WAYPOINT:
    should_publish = True

# 额外保险：WAYPOINT模式下绝对不发布
if self.flight_mode == FlightMode.WAYPOINT:
    should_publish = False
```

## 系统架构说明

### 控制权分配

根据v11架构设计，控制权分配如下：

1. **WAYPOINT模式**
   - 只有`waypoint_mission.py`发布到MAVROS
   - `mission_controller.py`不发布任何命令
   - 位置控制（PositionTarget）

2. **TRACKING模式**
   - `target_tracker.py`发布速度到`mission_controller.py`
   - `mission_controller.py`融合后发布到MAVROS
   - 速度控制（PositionTarget with velocity）

3. **其他模式（起飞/降落/解锁）**
   - 只有`mission_controller.py`发布到MAVROS
   - 速度控制

### 话题流向

```
WAYPOINT模式：
waypoint_mission --> MAVROS setpoint_raw/local

TRACKING模式：
target_tracker --> /drone_x/target_tracker/cmd_vel --> mission_controller --> MAVROS setpoint_raw/local

其他模式：
mission_controller --> MAVROS setpoint_raw/local
```

## 关键原则

1. **互斥控制**：同一时刻只能有一个节点向MAVROS发布控制命令
2. **模式隔离**：不同飞行模式的控制完全隔离，避免干扰
3. **明确权限**：每个模块只在自己负责的模式下发布命令

## 测试验证

1. **航点飞行测试**
   - 确认无人机平滑飞行，无抖动
   - 使用`rostopic hz`检查setpoint_raw/local话题频率应该稳定

2. **模式切换测试**
   - 从航点切换到追踪，控制权正确转移
   - 从追踪返回航点，控制权正确恢复

3. **话题监控**
   ```bash
   # 监控谁在发布控制命令
   rostopic echo /typhoon_h480_0/mavros/setpoint_raw/local --noarr
   ```

## 总结

通过确保在WAYPOINT模式下只有waypoint_mission发布控制命令，彻底解决了控制冲突导致的抖动问题。这是一个典型的多节点控制权管理问题，需要严格的互斥机制。
