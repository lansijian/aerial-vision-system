# v11.3.9 追踪和坐标发布修复 - 2025年10月16日

## 问题描述

用户报告：**无人机在执行航点任务时检测到行人后，没有进行有效的追踪和行人坐标信息的输出**

## 根本原因分析

### 1. ActorInfo坐标发布问题
- **原代码逻辑**：只在`flight_mode == "TRACKING"`时才发布ActorInfo
- **问题**：如果模式切换失败，坐标永远不会发布
- **影响**：记分系统收不到坐标信息，无法计算得分

### 2. 追踪模式切换失败
- **原代码限制**：`_tracking_status_callback`只在`state == 'EXECUTING'`时才处理
- **问题**：可能无人机还没进入EXECUTING状态，追踪请求被忽略
- **影响**：检测到目标后无法切换到追踪模式

### 3. flight_mode发布时机过晚
- **原代码逻辑**：只在起飞完成后才发布WAYPOINT模式
- **问题**：target_tracker不知道当前模式，默认状态可能不对
- **影响**：target_tracker不会检测目标或发布追踪请求

### 4. 追踪命令转发延迟
- **原代码逻辑**：waypoint_mission在20Hz的control_callback中才转发追踪命令
- **问题**：转发不够及时，可能丢失部分命令
- **影响**：追踪响应慢，可能抖动

## 修复方案

### 修复1：target_tracker.py - 立即发布坐标
```python
def _control_loop(self, event):
    with self.lock:
        # 持续检测目标并发布坐标信息
        target = self._select_target()
        
        if target and target.probability > self.min_confidence:
            # 无论什么模式，检测到目标就发布ActorInfo坐标信息（记分系统需要）
            actor_x, actor_y = self._compute_world_position(target)
            if actor_x is not None and actor_y is not None:
                self._publish_actor_info(actor_x, actor_y, target.Class)
                rospy.loginfo_throttle(2.0, 
                    f"[目标追踪] 发布{target.Class}色目标坐标: ({actor_x:.2f}, {actor_y:.2f})")
        
        # 后续处理模式切换和速度控制...
```

**关键改进**：
- ✅ 检测到目标立即发布坐标，不等待模式切换
- ✅ 记分系统能实时收到坐标信息
- ✅ 即使追踪失败，至少坐标已经发布

### 修复2：waypoint_mission.py - 即时转发
```python
def _tracking_cmd_callback(self, msg):
    """人体跟踪控制指令回调"""
    self.latest_tracking_cmd = msg
    self.last_tracking_control_time = rospy.Time.now()
    
    # 收到追踪命令时自动激活追踪模式
    if not self.tracking_active:
        self.tracking_active = True
        # 立即发布追踪状态
        self.tracking_status_pub.publish(Bool(data=True))
        rospy.loginfo(f"🎯 无人机{self.drone_id}: 收到追踪命令，激活追踪模式")
    
    # 立即转发追踪命令给mission_controller（不等待control_callback）
    self.tracking_control_pub.publish(msg)
    rospy.loginfo_throttle(2.0, 
        f"📡 无人机{self.drone_id}: 转发追踪命令 - "
        f"vx={msg.linear.x:.2f} vy={msg.linear.y:.2f} vz={msg.linear.z:.2f}")
```

**关键改进**：
- ✅ 收到追踪命令立即转发，不等待20Hz的control_callback
- ✅ 降低延迟，提高响应速度
- ✅ 同时发布追踪状态，确保模式切换

### 修复3：mission_controller.py - 早期发布模式
```python
def _handle_takeoff(self):
    """处理起飞状态（使用位置控制）"""
    # 起飞开始时就设置WAYPOINT模式（让target_tracker知道当前状态）
    if self.flight_mode != "WAYPOINT":
        self.flight_mode = "WAYPOINT"
        self.flight_mode_pub.publish("WAYPOINT")
        rospy.loginfo(f"[任务控制器] 设置初始飞行模式: WAYPOINT")
    
    # ... 起飞控制逻辑
```

**关键改进**：
- ✅ 起飞开始就发布WAYPOINT模式
- ✅ target_tracker从一开始就知道当前模式
- ✅ 可以正常检测目标并发布追踪请求

### 修复4：mission_controller.py - 放宽切换条件
```python
def _tracking_status_callback(self, msg):
    """追踪状态回调"""
    # 只要解锁后就可以切换模式（不限制在EXECUTING状态）
    if self.is_armed:
        if msg.data:
            # 开始追踪
            rospy.loginfo(f"[任务控制器] 收到追踪状态，切换到追踪模式")
            self.flight_mode = "TRACKING"
            self.flight_mode_pub.publish("TRACKING")
            # ...
        else:
            # 停止追踪，恢复航点
            rospy.loginfo(f"[任务控制器] 追踪结束，恢复航点模式")
            self.flight_mode = "WAYPOINT"
            self.flight_mode_pub.publish("WAYPOINT")
    else:
        rospy.logwarn_throttle(5.0, f"[任务控制器] 收到追踪状态但无人机未解锁")
```

**关键改进**：
- ✅ 移除`state == 'EXECUTING'`限制
- ✅ 只要解锁就可以切换模式
- ✅ 提高模式切换成功率

## 优化后的控制流程

```
1. 起飞开始
   ↓
2. mission_controller发布 flight_mode="WAYPOINT"
   ↓
3. target_tracker收到WAYPOINT模式，开始检测目标
   ↓
4. 检测到目标
   ↓
5. 立即发布ActorInfo坐标 (记分系统收到) ← 修复点1
   ↓
6. 发布追踪请求到 /drone_{id}/request_tracking_mode
   ↓
7. waypoint_mission收到请求，立即发布 tracking_status=True ← 修复点2
   ↓
8. mission_controller收到追踪状态（解锁即可，不限制状态） ← 修复点4
   ↓
9. 切换到TRACKING模式，发布 flight_mode="TRACKING"
   ↓
10. target_tracker收到模式变化，开始发布追踪速度命令
   ↓
11. waypoint_mission立即转发追踪命令 ← 修复点3
   ↓
12. mission_controller转发到MAVROS
   ↓
13. 无人机开始追踪目标
```

## 总结

本次修复参照v9.2稳定架构，彻底解决了：
1. ✅ 行人坐标信息不输出的问题
2. ✅ 检测到行人后不追踪的问题
3. ✅ 追踪模式切换失败的问题
4. ✅ 追踪响应延迟的问题

**关键思想**：
- **解耦坐标发布和模式切换**：检测到就发布，不等待切换
- **提前发布模式信息**：让所有节点尽早知道当前状态
- **即时转发命令**：减少延迟，提高响应速度
- **放宽切换条件**：只要解锁就可以切换，不限制状态
