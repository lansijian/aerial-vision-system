# v11.3.2 稳定版重构

**日期**: 2025-10-16  
**版本**: v11.3.2  
**作者**: AI Assistant

## 背景

用户反馈起飞后航点飞行仍然存在抖动问题，经过多次尝试修复未能解决。因此决定基于稳定的v10.1.2版本进行重构。

## 重构方案

### 1. 保留当前优点
- **位置控制**: 保留使用位置控制而非速度控制的方式
- **架构设计**: 保留waypoint_mission → mission_controller → MAVROS的统一架构
- **追踪集成**: 保留人体追踪与航点飞行的优先级切换机制

### 2. 采用v10.1.2稳定实现
- **控制逻辑**: 采用v10.1.2的PID控制和状态管理
- **起飞流程**: 使用v10.1.2验证过的平滑起飞方案
- **模式切换**: 使用v10.1.2的模式管理机制

## 主要修改

### waypoint_mission.py
基于v10.1.2的waypoint_navigator.py重写，主要变化：
1. **保留位置控制**: 使用位置误差计算速度命令，而非直接速度控制
2. **简化状态管理**: 移除复杂的状态机，采用简单可靠的逻辑
3. **控制算法**:
   ```python
   # 位置P控制器
   Kp = 0.5
   speed = position_error * Kp
   
   # 速度限制
   if speed > max_speed:
       speed = max_speed
   ```

### mission_controller.py  
基于v10.1.2的drone_controller.py重写，主要改进：
1. **平滑起飞控制**:
   ```python
   if height_error > 2.0:
       cmd.twist.linear.z = 1.0  # 远离目标，全速
   elif height_error > 1.0:
       cmd.twist.linear.z = 0.7  # 中等距离，减速
   else:
       cmd.twist.linear.z = 0.5  # 接近目标，慢速
   ```
2. **稳定的OFFBOARD切换**: 发送100个setpoint确保模式切换稳定
3. **命令转发**: 统一处理Twist到TwistStamped的转换

## 技术细节

### 坐标系转换
ENU坐标系到机体坐标系的转换：
```python
body_vx = enu_vx * cos(yaw) + enu_vy * sin(yaw)
body_vy = -enu_vx * sin(yaw) + enu_vy * cos(yaw)
```

### 航点到达判断
- 使用2D水平距离判断
- 阈值：0.3米（可配置）
- 到达后立即停止发送命令，避免抖动

### 控制频率
- mission_controller: 20Hz
- waypoint_mission: 50Hz
- 确保控制命令的连续性

## 解决的问题

1. **起飞抖动**: 通过分段速度控制解决
2. **航点飞行抖动**: 通过简化控制逻辑和到达后停止命令解决
3. **模式切换不稳定**: 通过充分的setpoint预发送解决
4. **控制冲突**: 通过统一的命令转发架构解决

## 测试要点

1. **起飞测试**:
   - 观察起飞是否平滑
   - 检查高度是否稳定在3米
   
2. **航点飞行测试**:
   - 观察飞行轨迹是否平滑
   - 检查到达航点后是否稳定悬停
   
3. **模式切换测试**:
   - 测试追踪模式切换响应
   - 验证追踪结束后能否恢复航点飞行

## 参数配置

### waypoint_mission参数
- `waypoint_reached_threshold`: 0.3米（航点到达阈值）
- `cruise_speed`: 5.0 m/s（巡航速度）

### mission_controller参数
- `takeoff_altitude`: 3.0米（起飞高度）
- `initial_delay`: 1.0秒（启动延迟）
