# v11.3.6 追踪接口修复

**日期**: 2025-10-16  
**版本**: v11.3.6  
**作者**: AI Assistant

## 🐛 问题描述

用户反馈：检测到行人后没有进行追踪任务。

## 🔍 问题分析

经过检查发现话题名称不匹配：

### target_tracker.py 发布的话题：
- `/drone_{id}/target_tracker/cmd_vel` - 追踪速度命令
- `/drone_{id}/request_tracking_mode` - 请求进入追踪模式

### waypoint_mission.py 原来订阅的话题：
- `/drone_{id}/tracking_status` ❌ (不存在)
- `/drone_{id}/tracking_control` ❌ (不存在)

## 🔧 解决方案

### 1. 修复waypoint_mission.py订阅
```python
# 订阅正确的话题
self.tracking_request_sub = rospy.Subscriber(
    f'/drone_{self.drone_id}/request_tracking_mode', 
    Bool, self._tracking_request_callback
)
self.tracking_cmd_sub = rospy.Subscriber(
    f'/drone_{self.drone_id}/target_tracker/cmd_vel', 
    Twist, self._tracking_cmd_callback
)
```

### 2. waypoint_mission作为中继
waypoint_mission现在作为中继节点，转发追踪命令给mission_controller：
```python
# 发布给mission_controller
self.tracking_status_pub.publish(Bool(data=True))
self.tracking_control_pub.publish(self.latest_tracking_cmd)
```

### 3. mission_controller接收转发
mission_controller订阅waypoint_mission发布的话题，并转发速度命令到MAVROS。

## 📊 控制流程

```
检测到人：
target_tracker ─(request_tracking_mode)─> waypoint_mission
target_tracker ─(cmd_vel)─> waypoint_mission ─(tracking_control)─> mission_controller ─(TwistStamped)─> MAVROS

恢复航点：
waypoint_mission ─(tracking_status=False)─> mission_controller
waypoint_mission ─(PositionTarget)─> MAVROS
```

## ✅ 修复效果

1. **追踪激活**: 检测到人时自动切换到追踪模式
2. **命令转发**: 追踪速度命令正确传递到MAVROS
3. **模式切换**: 目标丢失后自动恢复航点飞行
4. **状态同步**: mission_controller和waypoint_mission状态保持一致

## 💡 关键点

- waypoint_mission既直接控制航点（位置控制），又中继追踪命令（速度控制）
- 这种设计保证了追踪优先级高于航点飞行
- 1.5秒的追踪超时确保了及时恢复航点任务
