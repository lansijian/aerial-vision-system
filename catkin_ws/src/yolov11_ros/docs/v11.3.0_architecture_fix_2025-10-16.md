# v11.3.0 架构修复 - 2025年10月16日

## 问题根源

发现了系统架构中的**严重控制冲突**：

1. **waypoint_mission.py**（基于v9.2）直接发布PositionTarget到MAVROS
2. **mission_controller.py**（基于v10.1.2）期望接收Twist命令并转发到MAVROS
3. 两个节点同时向MAVROS发送不同类型的控制命令，导致抖动

## 解决方案

### 统一控制架构

```
waypoint_mission ─→ Twist ─→ mission_controller ─→ TwistStamped ─→ MAVROS
      ↓                             ↑
target_tracker ──→ Twist ────────────┘
```

### 主要修改

1. **waypoint_mission.py**
   - 移除直接发布到MAVROS
   - 改为发布Twist到`/drone_{id}/waypoint_cmd_vel`
   - 移除PositionTarget相关代码
   - 简化后台线程，只发送零速度保持活跃

2. **mission_controller.py**
   - 基于v10.1.2的稳定架构
   - 统一接收Twist命令
   - 转换为TwistStamped发送到MAVROS
   - 处理模式切换和起飞

## 控制流程

1. **起飞阶段**：mission_controller直接控制
2. **航点飞行**：waypoint_mission → mission_controller → MAVROS
3. **目标追踪**：target_tracker → mission_controller → MAVROS
4. **模式切换**：由mission_controller统一管理

## 关键改进

1. **消除冲突**：只有一个节点与MAVROS通信
2. **简化架构**：清晰的控制流
3. **保持兼容**：支持追踪/航点模式切换
4. **同时起飞**：所有无人机initial_delay=1.0秒
