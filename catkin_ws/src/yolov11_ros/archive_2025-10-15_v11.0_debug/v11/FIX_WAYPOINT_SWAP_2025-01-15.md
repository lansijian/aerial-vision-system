# 航点文件对调问题修复

**日期**：2025-01-15  
**版本**：v11.0  
**问题**：无人机1起飞后转圈，云台朝向飞行反方向

## 问题诊断

### 问题现象
- **drone_1**起飞后先往回飞，然后转向，看起来"转了个圈"
- 云台朝向与飞行方向相反

### 根本原因
**航点文件被对调了！**

#### 当前配置（错误）
| 无人机 | Spawn位置 | 第1个航点 | 第2个航点 | 问题 |
|--------|----------|-----------|-----------|------|
| drone_0 | (0, -3, 1) | (0, 0, 3) | (-15, 0, 3) | ✅ 正常 |
| drone_1 | (3, -3, 1) | (0, 0, 3) | (105, 0, 3) | ❌ 需要往回飞到(0,0)，再飞远到(105,0) |

#### 飞行路径分析（drone_1）
1. 起飞到 **(3, -3, 3)**
2. 第一个航点 **(0, 0, 3)** - 往西北方向飞回原点
3. 第二个航点 **(105, 0, 3)** - 往东飞很远

→ 形成"转圈"的视觉效果

### 对比旧版本
旧版本v10.1.2的航点配置：
- 旧版 drone_0 的航点 = 当前 drone_1 的航点（从(0,0)飞到(105,0)）
- 旧版 drone_1 的航点 = 当前 drone_0 的航点（从(0,0)飞到(-15,0)）

**结论**：航点文件在某次更新中被对调了！

## 修复方案

### 解决方法
交换 `waypoints_drone_0.json` 和 `waypoints_drone_1.json` 的内容

### 修复后配置（正确）
| 无人机 | Spawn位置 | 第1个航点 | 第2个航点 | 路径特征 |
|--------|----------|-----------|-----------|----------|
| drone_0 | (0, -3, 1) | (0, 0, 3) | (105, 0, 3) | 从原点向东巡检 |
| drone_1 | (3, -3, 1) | (0, 0, 3) | (-15, 0, 3) | 从附近向西巡检 |

### 飞行路径（修复后）
**drone_0**:
- 起飞 (0, -3, 3)
- → (0, 0, 3) - 向北3米
- → (105, 0, 3) - 向东飞行

**drone_1**:
- 起飞 (3, -3, 3)
- → (0, 0, 3) - 向西北3.6米
- → (-15, 0, 3) - 继续向西飞行

## 实施步骤

```bash
# 1. 备份drone_0航点
copy waypoints_drone_0.json waypoints_temp.json

# 2. 用drone_1航点覆盖drone_0
copy waypoints_drone_1.json waypoints_drone_0.json

# 3. 用备份覆盖drone_1
copy waypoints_temp.json waypoints_drone_1.json

# 4. 删除临时文件
del waypoints_temp.json
```

修复后：
- ✅ drone_0 和 drone_1 实现真正的"一正一反"巡检模式
- ✅ 两架无人机从各自spawn点附近开始巡检
- ✅ 不会出现"转圈"现象
- ✅ 云台朝向与飞行方向一致
- ✅ 高效覆盖搜索区域

drone_1: (3,-3) → (0,0) → (105,0) → ... （先回原点再向东，转圈）

## 技术说明

### 航点文件格式
```json
{
  "waypoints": [
    {
      "x": 0.0,        // 东向坐标（米）
      "y": 0.0,        // 北向坐标（米）
      "z": 3.0,        // 高度（米）
      "hover_time": 2.0,  // 悬停时间（秒）
      "loop": true     // 是否循环（仅第一个航点）
    },
    ...
  ]
}
```

### Spawn位置配置
在 `multi_drone_system.launch` 中：
- drone_0: `spawn_offset_x=0.0, spawn_offset_y=-3.0`
- drone_1: `spawn_offset_x=3.0, spawn_offset_y=-3.0`
